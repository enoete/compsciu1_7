Number systems & conversion

Four ways of writing down the same quantity. None of them is more "real" than another — decimal just happens to be the one you grew up with, because you have ten fingers.

🚗 The odometer

A car's odometer wheel spins 0-1-2-...-9, and the instant it would go to 10, it rolls back to 0 and bumps the wheel to its left instead. That single rule — when a digit runs out of symbols, it resets to zero and hands a "carry" to its neighbour — is the entire mechanism behind every number system there is.

Binary's odometer wheel just runs out one digit sooner. It only has two symbols, 0 and 1, so it rolls over on every single step: 0, 1, 10, 11, 100, 101, 110… The hero above is four of these wheels sitting side by side.

Converting decimal to any base — divide and read upward

Divide repeatedly by the target base, write down each remainder, and read the remainders from the last one up to the first.

42 ÷ 2 = 21 remainder 0 21 ÷ 2 = 10 remainder 1 10 ÷ 2 = 5 remainder 0 5 ÷ 2 = 2 remainder 1 2 ÷ 2 = 1 remainder 0 1 ÷ 2 = 0 remainder 1 Read the bold column bottom-to-top: 101010 ← that is 42 in binary

Converting any base back to decimal — multiply by place value and add

Every digit sits in a place worth a power of the base. Multiply each digit by its place value and add the results.

1 1 0 1 0 1 1 0 (binary 11010110) 128 + 64 + 0 + 16 + 0 + 4 + 2 + 0 = 128 + 64 + 16 + 4 + 2 = 214
The shortcut nobody tells you until later: binary, octal and hex are all powers of 2, so you never have to go through decimal to swap between them. Group binary digits in 3s for octal (2³ = 8) or in 4s for hex (2⁴ = 16), convert each little group on its own, and glue the results together. 1111 1111₂ groups into 1111 1111 → F F → FF in hex, no decimal step required.

Binary arithmetic

Computers only really know how to do one arithmetic trick well: add. Subtraction, multiplication, even the two's complement you're about to meet — all of it eventually reduces to addition circuitry.

🚗 Same odometer, now add two of them

Column addition in binary rolls over exactly like the odometer did: once a column's total reaches "2", it can't be written with a single binary digit, so it resets to 0 and carries 1 into the column on its left — the exact same move as 9 + 1 rolling an odometer wheel to 0 and bumping its neighbour.

Positive and negative numbers

Binary has no minus sign lying around. Every method here is a different trick for sneaking negative numbers into a pattern of plain 0s and 1s.

1. Sign & magnitude

The leftmost bit is just a flag: 0 for positive, 1 for negative. The rest of the bits are the ordinary binary magnitude. +10 = 00001010, −10 = 10001010.

The problem: 00000000 and 10000000 are both "zero" — positive zero and negative zero, two different bit patterns meaning the same thing. Circuits that add and subtract have to special-case this everywhere. Nobody builds hardware this way.

2. One's complement

Flip every bit. +15 = 00001111, so −15 = 11110000. Quick to compute, but it inherits the exact same two-zeros problem as sign & magnitude (00000000 and 11111111 both mean zero).

3. Two's complement — what real computers use

Flip every bit, then add 1. That one extra step is worth an entire lecture's problems disappearing: there is exactly one zero, and the same addition circuit that handles positive numbers handles negative ones too, with no special cases.

Start with +15: 00001111 Flip every bit: 11110000 Add 1: + 00000001 ----------- −15 in two's complement: 11110001

🕐 The circular clock

An 8-bit two's complement number line is a circle, not a straight line. Count down from 00000000 and instead of running off the end, you wrap straight around to 11111111 — which is exactly the pattern for −1. Keep going backwards and you pass through −2, −3… all the way to the most negative number the pattern allows, at which point it wraps forward again. There is no edge to fall off.

Floating-point numbers

The topic that causes the most grief in this unit — and almost always for the same three avoidable reasons. Get the five-step drill into your hand and it stops being mysterious.

🔬 Scientific notation, wearing binary

You already do this in Chemistry: instead of writing 300,000,000, you write 3.0 × 10⁸. Three parts — a sign, a set of significant digits, and a power of ten telling you how far to slide the decimal point to get the real number back.

Floating point is the identical idea with one change: the power is of 2, not 10, because binary is all a computer has. Sign, significant bits (the mantissa), and a power of two (the exponent) — that's the whole format.

FieldWidthJob
Sign (S)1 bit0 = positive, 1 = negative
Exponent (E)8 bitsPower of 2, stored with a bias of 127

Try normalizing it yourself first

Before the five-step drill, get a feel for the one move that trips people up: sliding the point. A normalized binary number always has exactly one 1 sitting just before the point. Slide the point on 1011.01 until that's true, and watch the exponent count the slides for you.

The five-step drill: Sign · Binarize · Normalize · Exponent · Mantissa. Every encoding question in this section, and on the exam, is these five steps in this order. Nothing else.

Worked example: encode 12.75

1. Sign 12.75 is positive → S = 0 2. Binarize 12 → 1100 (repeated division) 0.75 → .11 (repeated multiplication: .75×2=1.5→1, .5×2=1.0→1) 12.75 → 1100.11 3. Normalize 1100.11 = 1.10011 × 2³ (point moved 3 places left) 4. Exponent actual exponent = 3 stored = 3 + 127 = 130 = 10000010 5. Mantissa take what's after the leading "1.": 10011 pad with zeros to 23 bits: 10011000000000000000000 Final: 0 | 10000010 | 10011000000000000000000

Now you drive: encode −3.25

Going backwards: decode the bits

📖 Reading the recipe card back to the dish

Roughly half of what gets examined on floating point is this direction: you're handed the 32 bits and asked what decimal they represent. It's the same five ingredients, just combined in reverse — and it's where the three classic mistakes below actually cost marks.

Worked example: decode 0 | 10000001 | 01000000000000000000000

1. Sign S = 0 → positive 2. Un-bias exponent stored 10000001 = 129 → actual = 129 − 127 = 2 3. Restore mantissa bits 01000... → put the implied "1." back → 1.01 4. Combine 1.01₂ × 2² = 101.0₂ = 5 + 0 = 5.0

Now you drive: decode 0 | 10000001 | 10100000000000000000000

The three mistakes that cost the most marks
  • Forgetting the implicit leading 1. The mantissa bits are only the part after "1." — a stored mantissa of 10100... means the real value is 1.101, not 0.101.
  • Forgetting to un-bias the exponent. A stored exponent is never the real exponent. Always subtract 127 first. Stored 130 means actual +3, not +130.
  • Mixing up binary and decimal place value. Binary 0.1 is decimal 0.5, not decimal 0.1. This single confusion is why 0.1 + 0.2 famously doesn't equal exactly 0.3 in most programming languages.
Where this actually shows up: 3D graphics and game physics, GPS coordinates precise to the metre over a planet-sized number line, weather and orbital simulations, and every machine-learning model doing millions of these multiplications a second. The format you just hand-decoded is running underneath all of it.

Character encoding

Text is numbers wearing a costume. Every letter, digit and punctuation mark on your keyboard is stored as one of the binary patterns you've spent this whole page learning to build.

📕 A phrasebook, agreed in advance

A phrasebook only works because both sides agreed beforehand that a certain phrase means a certain thing. ASCII is exactly that agreement, made once in the 1960s: everyone's computer agrees that the pattern 01000001 means the capital letter A. Without that shared agreement, every text file would be gibberish the moment it left the machine that wrote it.

SchemeBitsCharactersNotes
ASCII7128English letters, digits, punctuation, control codes
Extended ASCII8256ASCII plus 128 more — accents, symbols, box-drawing
BCD4 per digit0–9Each decimal digit stored as its own 4-bit binary value
Unicode (UTF-8)8–32, variable150,000+Every script and emoji on Earth, backward-compatible with ASCII
Why Unicode had to exist: 128 ASCII slots cannot hold Mandarin, Arabic, Devanagari, and every other script humans actually write in — let alone emoji. Unicode assigns a unique number to every character in every living writing system, and UTF-8 is simply an efficient way of packing those numbers into bytes.
